# Relay NW Pilot Onboarding

Use this for white-glove pilot customers. Do not treat SMS as production-reliable until the customer's A2P 10DLC registration or campaign update is complete and approved.

## 1. Create The Account

Apply `supabase.sql`, then provision the tenant:

```bash
ACCOUNT_SLUG="abc-plumbing" \
BUSINESS_NAME="ABC Plumbing" \
OWNER_PHONE_NUMBER="+15557654321" \
TWILIO_PHONE_NUMBER="+15551234567" \
INTAKE_URL="https://relay-nw.com/intake" \
OWNER_EMAIL="owner@example.com" \
CALL_MODE="forwarding" \
SMS_ENABLED="false" \
npm run provision:account
```

Then create or invite the same owner email in Supabase Auth. The first successful magic-link login binds that Supabase Auth user to the `account_users` row when `user_id` is still empty.

Human access is now resolved from:

```text
Supabase Auth user -> account_users -> account_id -> account settings and scoped data
```

`RELAY_DEFAULT_ACCOUNT_SLUG` remains only a fallback for legacy/manual flows. Do not use it as the isolation boundary for customer access.

## 2. Configure Twilio

Set the customer's Relay NW Twilio number webhooks:

- Voice webhook: `https://relay-nw.vercel.app/api/twilio/voice`
- Messaging webhook: `https://relay-nw.vercel.app/api/twilio/sms`
- Use HTTP `POST` for both.

For direct-call pilots, confirm `/api/twilio/voice-status` is used as the dial callback generated by Relay. For forwarding pilots, confirm the existing carrier number forwards missed, busy, or unreachable calls to the Relay NW Twilio number.

## 3. A2P 10DLC

The founder's Sole Proprietor A2P registration is only suitable for founder testing and any use it actually covers. For customer use, complete or update the proper A2P 10DLC brand/campaign before relying on customer-facing missed-call SMS.

Track the customer campaign status in `account_settings.a2p_registration_status`.

## 4. Production Checks

- Sentry DSN is set in production.
- `ALLOW_UNSIGNED_TWILIO_WEBHOOKS=false`.
- `SMS_ENABLED=false` until A2P is ready or a controlled test is planned.
- Customer-specific settings live in `account_settings` and `account_phone_numbers`, not only env vars.
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` is set so Supabase Auth magic links work.
- `RESEND_API_KEY`, `ALERT_FROM_EMAIL`, and `ADMIN_ALERT_EMAIL` are set before enabling owner/admin email alerts.
- Each owner email exists in both Supabase Auth and `account_users`.
- Secrets remain env-only: Supabase service role key, Twilio auth token, OpenAI key, Sentry token, and future email provider keys.

## 5. Acceptance Test

Before charging the pilot:

- missed call creates one account-scoped lead
- duplicate Twilio retry does not create a duplicate lead
- voicemail recording attaches to the lead
- voicemail summary works when `OPENAI_API_KEY` is configured
- missed-call SMS sends only when A2P/SMS readiness is approved
- STOP opt-out suppresses future SMS for that account
- inbound reply appears in the lead inbox
- SMS status callback updates lead/message state
- recent webhook events show account, CallSid/MessageSid, and sanitized payload metadata
- owner can sign in at `/login` and can only see their account's `/leads`, `/ops`, recordings, health-check, and SMS-test routes
- owner receives a new missed-call email alert
- owner receives a voicemail-ready email when transcription completes
- admin receives operational alerts for SMS, recording, transcription, or webhook failures
- Sentry captures a forced server-side test error
